What I'm learning now

A focused deep-dive on mutation testing with Stryker for TypeScript teams.

Stryker Mutation Testing

Stryker is the gold standard for Mutation Testing across JavaScript/TypeScript, .NET, and Scala. It doesn’t test your code — it tests your tests by injecting tiny bugs ("mutants") into the source.

At-a-glance

  • Mutation Score: Percentage of mutants that are killed — the real metric of test effectiveness.
  • Workflow: Mutate → Test → Analyze. If tests fail, the mutant is Killed; if tests pass, it Survived.
Explore Stryker

Core details for a professional setup

1. TypeScript-specific intelligence

  • AST-based mutations: Uses the TypeScript AST and skips interfaces or type definitions.
  • In-memory type checking: Mutants that don’t compile are marked CompileError and ignored.

2. Performance optimization

  • Coverage analysis: coverageAnalysis: 'perTest' runs only the tests that touch a mutant.
  • Parallelism: Worker model runs test runners across CPU cores.
  • Incremental mode: Mutate only files changed in the current PR.

3. Integration & reporting

  • Runners: Jest, Vitest, Mocha, Jasmine, and Karma.
  • Reporters: HTML reports that show surviving mutants line-by-line.
  • Dashboard: Host reports and surface a Mutation Score badge.

Why use Stryker?

1. Coverage isn’t enough

100% line coverage can still mean zero assertions. Stryker proves what’s actually verified.

2. Catch leaky edge cases

Boundary mutations (like > to <) expose real-world bugs early.

3. Safer refactoring

A high mutation score gives proof that critical logic changes will be caught by tests.

4. Gamify quality

Hunting surviving mutants is motivating and improves the culture of thoughtful testing.

Professional implementation note

  1. Set a baseline: First run to see your starting score (often 40–60%).
  2. Target critical paths: Use mutate to focus on business-critical modules.
  3. Enforce in CI: Configure thresholds.break in stryker.config.json.
